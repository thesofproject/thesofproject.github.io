Audio Buffer & Stream Management API#

The Audio Buffer and Stream Management API governs intermediate audio data storage, circular stream pointer tracking, inter-component buffer negotiation, and lockless cross-core ring buffer streaming.

Buffer Subsystem Architecture#

SOF audio buffers decouple processing components, absorbing execution jitter and rate differences:

+-------------------+                               +-------------------+
| Upstream Copier   |                               | Downstream Mixer  |
| (Source Component)|                               | (Sink Component)  |
+---------+---------+                               +---------^---------+
          |                                                   |
          | audio_stream_produce()      audio_stream_consume()|
          v                                                   |
+---------+---------------------------------------------------+---------+
|                       struct comp_buffer                              |
|  - id, size, free, avail, flags                                       |
|  - source -> upstream comp_dev        sink -> downstream comp_dev    |
|  - stream (struct audio_stream)                                       |
|    * r_ptr, w_ptr (circular byte/frame pointers)                      |
|    * addr, end_addr (underlying audio memory buffer)                  |
+-----------------------------------------------------------------------+

Buffer Types & Usage Profiles#

  1. Interconnect Buffers (`struct comp_buffer`): Allocated in internal SRAM via buffer_alloc() or rballoc(). Connects adjacent components within a pipeline. Supports transaction callbacks (BUFF_CB_TYPE_*) to notify consumers when fresh audio data is written.

  2. Abstract Audio Buffers (`struct sof_audio_buffer`): Unified buffer descriptor providing polymorphic operations (struct audio_buffer_ops) across legacy component buffers (BUFFER_TYPE_LEGACY_BUFFER) and lockless ring buffers (BUFFER_TYPE_RING_BUFFER).

  3. Lockless Ring Buffers (`struct ring_buffer`): Designed for cross-core audio streaming (such as Inter-Domain Communication between Core 0 and secondary DSP cores). Lockless atomic read/write head updates eliminate spinlock contention between cores.

  4. Circular Audio Streams (`struct audio_stream`): Format-aware circular buffer tracking sample rates, channels, and bit depths, enabling sample-accurate and frame-accurate data production and consumption.

Buffer type identifiers

Legacy comp_buffer type (pipeline 1.0).

BUFFER_TYPE_RING_BUFFER#

Lockless async circular ring buffer type (cross-core).

Buffer callback types

BUFF_CB_TYPE_PRODUCE#

Callback triggered on buffer produce.

BUFF_CB_TYPE_CONSUME#

Callback triggered on buffer consume.

Buffer parameter update modes

BUFFER_UPDATE_IF_UNSET#

Update buffer parameters only if currently unset.

BUFFER_UPDATE_FORCE#

Force update buffer parameters regardless of current state.

Buffer parameter bitmasks

BUFF_PARAMS_FRAME_FMT#

Buffer parameter bitmask: frame format.

BUFF_PARAMS_BUFFER_FMT#

Buffer parameter bitmask: buffer format.

BUFF_PARAMS_RATE#

Buffer parameter bitmask: sample rate.

BUFF_PARAMS_CHANNELS#

Buffer parameter bitmask: channels count.

Buffer memory sharing usage

BUFFER_USAGE_SHARED#

Buffer used by multiple DSP cores and/or HW blocks.

BUFFER_USAGE_NOT_SHARED#

Buffer only used by one HW block.

struct audio_stream#
#include <src/include/sof/audio/audio_stream.h>

Audio stream is a circular buffer aware of audio format of the data in the buffer so provides API for reading and writing not only bytes, but also samples and frames.

Audio stream does not perform any memory allocations. A client (a component buffer or dma) must allocate the memory for the underlying data buffer and provide it to the initialization routine.

Once the client is done with reading/writing the data, it must commit the consumption/production and update the buffer state by calling audio_stream_consume()/audio_stream_produce() (just a single call following series of reads/writes).
