Scheduling Infrastructure API#

Sound Open Firmware (SOF) implements a multi-tiered, real-time task scheduling infrastructure deeply integrated with the underlying Zephyr RTOS. The scheduling architecture accommodates diverse audio execution constraints, ranging from hard real-time, zero-jitter low-latency hardware streaming to asynchronous, compute-intensive data processing algorithms.

Architecture & Execution Domains#

SOF partitions firmware execution across four distinct scheduling domains:

+--------------------+     +------------------------+
| Hardware Timer     |     | DMA Interrupt          |
| (1ms / 500us tick) |     | (Transfer complete)    |
+---------+----------+     +-----------+------------+
          |                            |
+---------v----------------------------v------------+
|             Low-Latency (LL) Domain               |
|   - zephyr_domain.c / zephyr_dma_domain.c         |
|   - Dedicated real-time LL thread (zephyr_ll.c)   |
|   - Hard real-time audio components               |
+---------+----------------------------+------------+
          | LL Tick                    | LL Tick
          v                            v
+-----------------------+    +----------------------+
| Data Processing (DP)  |    | Thread With Budget   |
|  - zephyr_dp_schedule |    |  - zephyr_twb_sched  |
|  - Preemptible worker |    |  - Budgeted thread   |
|    threads            |    |  - Dynamic priority  |
|  - Zephyr EDF kernel  |    |    demotion/restore  |
|  - IPC command queue  |    |  - IDC/background    |
+-----------------------+    +----------------------+

  1. Low-Latency (LL) Scheduler: Hard real-time, deterministic task execution. Tasks run within a dedicated high-priority Zephyr thread pinned to each core (ll_thread0, etc.). Work items execute in strict priority order without sleeping or yielding. The LL scheduler supports two primary clock domains:

    • Timer Domain (SOF_SCHEDULE_LL_TIMER): Driven by periodic hardware timer interrupts (1000 µs default, 500 µs on AMD ACP platforms).

    • DMA Domain (SOF_SCHEDULE_LL_DMA): Driven directly by hardware DMA completion interrupts.

  2. Data Processing (DP) Scheduler (SOF_SCHEDULE_DP): Manages asynchronous, compute-heavy pipeline modules (e.g. ASRC, Smart Amp, ML keyword spotters). Each DP task is assigned its own preemptible Zephyr thread running at a lower priority than the LL domain. After every LL tick, the scheduler evaluates task buffer readiness across sinks and sources, calculates the task’s deadline timestamp, and configures the Zephyr kernel’s Earliest Deadline First (EDF) scheduler via k_thread_absolute_deadline_set().

  3. Thread With Budget (TWB) Scheduler (SOF_SCHEDULE_TWB): Provides CPU cycle limits for non-pipeline background tasks (such as Inter-Domain Communication or heavy diagnostics) to prevent systemic starvation. When a task consumes its allotted cycle budget during a tick, Zephyr time slicing triggers a callback that drops its priority to CONFIG_TWB_THREAD_LOW_PRIORITY. At the next LL tick, the cycle consumption is reset and standard priority is restored.

  4. Legacy Earliest Deadline First (EDF) Workqueue (SOF_SCHEDULE_EDF): Deprecated for audio pipelines. On Zephyr-based firmware, EDF is implemented as a single-thread delayed workqueue (edf_workq) dedicated exclusively to host IPC message dispatch. New audio pipelines must use the DP or LL schedulers.

Task Lifecycle & State Machine#

All tasks scheduled within SOF transition through standardized lifecycle states:

          +-----------------------+
          |  SOF_TASK_STATE_INIT  | <--- schedule_task_init()
          +-----------+-----------+
                      | schedule_task()
                      v
          +-----------------------+
+-------> |  SOF_TASK_STATE_QUEUED| <---------------------------+
|         +-----------+-----------+                             |
|                     | Tick / Event trigger                    |
|                     v                                         |
|         +-----------------------+                             |
|         |  SOF_TASK_STATE_RUNNING                             |
|         +-----+-----------+-----+                             |
|               |           |                                   |
|   RESCHEDULE  |           | COMPLETED                         |
+---------------+           v                                   |
|                 +-------------------+                         |
|                 |    COMPLETED      |                         |
|                 +---------+---------+                         |
|                           |                                   |
|  schedule_task_cancel()   |                                   |
+--------------+            |                                   |
               |            |                                   |
               v            v                                   |
          +-----------------------+                             |
          |  SOF_TASK_STATE_CANCEL|                             |
          +-----------+-----------+                             |
                      | schedule_task_free()                    |
                      v                                         |
          +-----------------------+                             |
          |   SOF_TASK_STATE_FREE |                             |
          +-----------------------+                             |

  • SOF_TASK_STATE_INIT: Task descriptor allocated and bound to a scheduler.

  • SOF_TASK_STATE_QUEUED: Task enqueued in the scheduler run list awaiting trigger conditions.

  • SOF_TASK_STATE_RUNNING: Task currently executing its run() callback.

  • SOF_TASK_STATE_RESCHEDULE: Periodic task completed a processing chunk and requested rescheduling.

  • SOF_TASK_STATE_COMPLETED: One-shot task finished; removed from active scheduling until re-triggered.

  • SOF_TASK_STATE_CANCEL: Task was cancelled and will be safely dequeued before releasing memory.

  • SOF_TASK_STATE_FREE: Task resources and thread handles released.

enumerator SOF_SCHEDULE_EDF#

Earliest Deadline First (EDF) scheduler.

Deprecated:

Deprecated for modern audio pipeline processing. In Zephyr-based builds, EDF is implemented as a delayed workqueue (edf_workq) retained for host IPC processing and legacy KPB draining tasks until migration. Audio pipeline components should use SOF_SCHEDULE_DP for preemptible deadline-driven tasks or SOF_SCHEDULE_LL_TIMER / SOF_SCHEDULE_LL_DMA for hard real-time tasks.

enumerator SOF_SCHEDULE_LL_TIMER#

Low Latency timer domain scheduler.

Executes tasks immediately upon expiration of the primary hardware timer tick.

enumerator SOF_SCHEDULE_LL_DMA#

Low Latency DMA interrupt domain scheduler.

Executes tasks immediately upon scheduling component’s DMA transfer completion interrupt.

enumerator SOF_SCHEDULE_DP#

Data Processing (DP) worker thread scheduler.

Preemptible Zephyr worker thread per SOF task. Evaluates task readiness after each Low-Latency (LL) tick, setting absolute deadlines in Zephyr EDF.

enumerator SOF_SCHEDULE_TWB#

Tasks With Budget (TWB) scheduler.

Preemptible Zephyr thread per SOF task with a pre-allocated cycle budget renewed every system tick. Drops thread priority on budget exhaustion to prevent system starvation.

enumerator SOF_SCHEDULE_COUNT#

int schedule_task_init(struct task *task, const struct sof_uuid_entry *uid, uint16_t type, int16_t priority, enum task_state (*run)(void *data), void *data, uint16_t core, uint32_t flags)#

Initialize a scheduling task and bind it to the registered scheduler for its type and core.

Validates scheduler type and searches registered schedulers. User schedulers look up the target core via arch_user_schedulers_get_for_core(core), whereas kernel schedulers look up via arch_schedulers_get() on the calling core. Therefore, kernel task initialization must execute directly on the target core. Initializes task properties, priority, execution callback, and sets task state to SOF_TASK_STATE_INIT.

Parameters:

  • task – [out] Task structure to initialize.

  • uid – [in] Statically assigned task UUID entry.

  • type – [in] Scheduler type (SOF_SCHEDULE_*).

  • priority – [in] Task scheduling priority (lower values indicate higher priority).

  • run – [in] Execution callback function returning task_state.

  • data – [in] Private context pointer passed to run callback.

  • core – [in] DSP core ID on which the task should execute.

  • flags – [in] Task-specific scheduling flags.

Returns:

0 on success, -EINVAL if type >= SOF_SCHEDULE_COUNT, -ENODEV if scheduler cannot be found.
