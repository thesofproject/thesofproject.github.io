70 /* Driver sends the DMA Control parameter in order to initialize or modify
71 * DMA gateway configuration outside of a stream lifetime. Typically a DMA
72 * gateway is initialized during pipeline creation when a Copier module is
73 * instantiated and attached to that gateway. Similarly the gateway is
74 * de-initialized when the Copiers parent pipeline is being destroyed.
75 * However sometimes the driver may want to control the gateway before or
76 * after a stream is being attached to it.
77 *
78 * The data of DMA Control parameter starts with DmaControl structure
79 * optionally followed by the target gateway specific data (that may consist
80 * of two parts, the former coming from NHLT BIOS tables and the latter
81 * aux_config in form of TLV list provided by the driver).
82 */
83 IPC4_DMA_CONTROL = 5,
84
85 /* Driver sets this parameter to control state of FW logging. Driver may
86 * enable logging for each core and specify logging level. Driver also
87 * configures period of aging and FIFO full timers. Aging timer period
88 * specifies how frequently FW sends Log Buffer Status notification for new
89 * entries in case the usual notification sending criteria are not met
90 * (half of the buffer is full). Fifo full timer period specifies the latency
91 * of logging "dropped log entries" information after the content is consumed
92 * by the driver but no new log entry appears (which would trigger logging
93 * "dropped entries" as well).
94 *
95 * SystemTime property must be provided by the driver prior to enabling
96 *the logs for the first time, otherwise error is raised by FW since
97 * it will not be able to translate log event timestamps into the host
98 * CPU clock domain.
99 *
100 * Log FIFO content is reset on logs enabled by the driver, so the RP
101 * is expected to be 0, however the driver should not assume that value
102 * but just read the RP from FW Registers instead.
103 */
104 IPC4_ENABLE_LOGS = 6,
