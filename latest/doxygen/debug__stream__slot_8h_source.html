17/*
18 * This file describes how Debug Stream can be transported over debug
19 * window memory slot. The debug stream is an abstract media API for
20 * passing debug data records from SOF DSP to the host system for
21 * presentation. The debug stream records are described in debug_stream.h.
22 *
23 * This example describes how Debug Stream data is transferred from
24 * DSP to host side using a debug memory window slot. To learn more
25 * see soc/intel/intel_adsp/common/include/adsp_debug_window.h
26 * under Zephyr source tree.
27 *
28 * DEBUG_STREAM slot is reserved from SRAM window and a header is
29 * written in the beginning of the slot. The header is a static data
30 * structure that is initialized once at DSP boot time. All elements
31 * in bellow example are 32-bit unsigned integers:
32 *
33 * --------------------------------------------------
34 * | id = DEBUG_STREAM_IDENTIFIER |
35 * | total_size = 4096 |
36 * | num_sections = CONFIG_MP_MAX_NUM_CPUS * |
37 * | section_descriptor [] = { |
38 * | { |
39 * | core_id = 0 |
40 * | size = 1344 |
41 * | offset = 64 |
42 * | } |
43 * | { |
44 * | core_id = 1 |
45 * | size = 1344 |
46 * | offset = 1344+64 |
47 * | } |
48 * | { |
49 * | core_id = 2 |
50 * | size = 1344 |
51 * | offset = 2*1344+64 |
52 * | } |
53 * | } |
54 * | <padding> |
55 * -------------------------------------------------- n * 64 bytes
56 * * CONFIG_MP_MAX_NUM_CPUS is 3 in this example
57 *
58 * The header contains generic information like identifier, total
59 * size, and number of sections. After the generic fields there is an
60 * array of section descriptors. The array has 'num_sections' number
61 * of elements. Each element in the array describes a circular buffer,
62 * one for each DSP core.
63 *
64 * The remaining memory in the debug window slot is divided between
65 * those sections. The buffers are not necessarily of equal size, like
66 * in this example. The circular buffers are all cache line aligned,
67 * 64 in this example. One section looks like this:
68 *
69 * -------------------------------------------------- ---
70 * | next_seqno = <counter for written objects> | |
71 * | w_ptr = <write position in 32-bit words> | 1344 bytes
72 * | buffer_data[1344/4-2] = { | |
73 * | <debug data records> | |
74 * | } | |
75 * -------------------------------------------------- ---
76 *
77 * The data records are described in debug_strem.h. In the case of
78 * debug window memory slot the next record should always be aligned
79 * to word (4-byte) boundary.
80 *
81 * The debug stream writes the records of abstract data to the
82 * circular buffer, and updates the w_ptr when the record is
83 * completely written. The host side receiver tries to keep up with the
84 * w_ptr and keeps track of its read position.
85 *
86 * The size of the record is written - again - after each record and
87 * before the next. This is to allow parsing the stream backwards in
88 * an overrun recovery situation. The w_ptr value is updated last,
89 * when the record is completely written.
90 */
