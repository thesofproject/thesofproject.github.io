11/*
12 * This file describes how Debug Stream can be transported over debug
13 * window memory slot. The debug stream is an abstract media API for
14 * passing debug data records from SOF DSP to the host system for
15 * presentation. The debug stream records are described in debug_stream.h.
16 *
17 * This example describes how Debug Stream data is transferred from
18 * DSP to host side using a debug memory window slot. To learn more
19 * see soc/intel/intel_adsp/common/include/adsp_debug_window.h
20 * under Zephyr source tree.
21 *
22 * DEBUG_STREAM slot is reserved from SRAM window and a header is
23 * written in the beginning of the slot. The header is a static data
24 * structure that is initialized once at DSP boot time. All elements
25 * in bellow example are 32-bit unsigned integers:
26 *
27 * --------------------------------------------------
28 * | id = DEBUG_STREAM_IDENTIFIER |
29 * | total_size = 4096 |
30 * | num_sections = CONFIG_MP_MAX_NUM_CPUS * |
31 * | section_descriptor [] = { |
32 * | { |
33 * | core_id = 0 |
34 * | size = 1344 |
35 * | offset = 64 |
36 * | } |
37 * | { |
38 * | core_id = 1 |
39 * | size = 1344 |
40 * | offset = 1344+64 |
41 * | } |
42 * | { |
43 * | core_id = 2 |
44 * | size = 1344 |
45 * | offset = 2*1344+64 |
46 * | } |
47 * | } |
48 * | <padding> |
49 * -------------------------------------------------- n * 64 bytes
50 * * CONFIG_MP_MAX_NUM_CPUS is 3 in this example
51 *
52 * The header contains generic information like identifier, total
53 * size, and number of sections. After the generic fields there is an
54 * array of section descriptors. The array has 'num_sections' number
55 * of elements. Each element in the array describes a circular buffer,
56 * one for each DSP core.
57 *
58 * The remaining memory in the debug window slot is divided between
59 * those sections. The buffers are not necessarily of equal size, like
60 * in this example. The circular buffers are all cache line aligned,
61 * 64 in this example. One section looks like this:
62 *
63 * -------------------------------------------------- ---
64 * | next_seqno = <counter for written objects> | |
65 * | w_ptr = <write position in 32-bit words> | 1344 bytes
66 * | buffer_data[1344/4-2] = { | |
67 * | <debug data records> | |
68 * | } | |
69 * -------------------------------------------------- ---
70 *
71 * The data records are described in debug_strem.h. In the case of
72 * debug window memory slot the next record should always be aligned
73 * to word (4-byte) boundary.
74 *
75 * The debug stream writes the records of abstract data to the
76 * circular buffer, and updates the w_ptr when the record is
77 * completely written. The host side receiver tries to keep up with the
78 * w_ptr and keeps track of its read position.
79 *
80 * The size of the record is written - again - after each record and
81 * before the next. This is to allow parsing the stream backwards in
82 * an overrun recovery situation. The w_ptr value is updated last,
83 * when the record is completely written.
84 */
