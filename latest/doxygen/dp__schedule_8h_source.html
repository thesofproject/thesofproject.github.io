120/*
121 * Keeps the scheduler_dp_thread_ipc() flow simple - just one call that does all
122 * the IPC-message specific parameter packing internally. This is slightly
123 * suboptimal because IPC parameters first have to be collected in this
124 * structure and then packed in DP-accessible memory inside
125 * scheduler_dp_thread_ipc(). This could be split into two levels, by adding
126 * IPC-specific functions like ipc_flatten_pipeline_state() and similar, but
127 * that would add multiple functions to the API.
128 */

132 * only valid until scheduler_dp_thread_ipc() returns; ipc_thread_flatten() copies
133 * it by value into DP-thread-accessible memory before the DP thread runs init().
134 */
